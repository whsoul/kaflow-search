# Repository Instructions

## Public pull requests

- Treat pull request titles and descriptions as public, user-facing content.
- Do not mention Codex or AI assistance in branch names, commit messages, pull request titles, or pull request descriptions unless the user explicitly requests it.
- Keep them concise: summarize the visible change and its user impact only.
- Do not include internal reasoning, implementation history, investigation details, environment information, exact validation dimensions, or verbose test logs unless they are essential for reviewers.
- Avoid disclosing security-sensitive or operational details. When more context is necessary, share only the minimum needed to review the change safely.
- Prefer a short `Summary` with a few bullets. Add testing details only when they materially help reviewers evaluate risk.
